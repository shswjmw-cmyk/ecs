## 3. 数据表设计

### 3.1 用户表 (users)

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id VARCHAR(64) UNIQUE NOT NULL COMMENT '工号/用户 ID',
  name VARCHAR(128) NOT NULL COMMENT '姓名',
  email VARCHAR(255) COMMENT '邮箱',
  avatar_url VARCHAR(512) COMMENT '头像 URL',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

### 3.2 项目表 (projects)

```sql
CREATE TABLE projects (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(256) NOT NULL COMMENT '项目名称',
  description TEXT COMMENT '项目描述',
  owner_id BIGINT NOT NULL COMMENT '项目负责人',
  team_id BIGINT COMMENT '所属团队 ID',
  status TINYINT DEFAULT 1 COMMENT '状态：1-进行中 2-已归档 3-已删除',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_owner_id (owner_id),
  INDEX idx_team_id (team_id),
  FOREIGN KEY (owner_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目表';
```

### 3.3 团队成员表 (project_members)

```sql
CREATE TABLE project_members (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  project_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  role TINYINT DEFAULT 1 COMMENT '角色：1-成员 2-管理员',
  joined_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_project_user (project_id, user_id),
  INDEX idx_project_id (project_id),
  INDEX idx_user_id (user_id),
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目成员表';
```

### 3.4 访谈表 (interviews)

```sql
CREATE TABLE interviews (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(256) NOT NULL COMMENT '访谈标题',
  research_goal TEXT NOT NULL COMMENT '研究目标',
  project_id BIGINT NOT NULL COMMENT '关联项目',
  creator_id BIGINT NOT NULL COMMENT '创建人',
  status TINYINT DEFAULT 1 COMMENT '状态：1-草稿 2-进行中 3-已完成 4-已归档',
  interview_time DATETIME COMMENT '访谈时间',
  duration_seconds INT COMMENT '访谈时长 (秒)',
  audio_url VARCHAR(512) COMMENT '录音文件 URL',
  audio_source TINYINT COMMENT '音频来源：1-实时录制 2-文件上传',
  summary TEXT COMMENT '访谈总结',
  editor_id BIGINT COMMENT '最后编辑人',
  edited_at DATETIME COMMENT '最后编辑时间',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_project_id (project_id),
  INDEX idx_creator_id (creator_id),
  INDEX idx_status (status),
  FULLTEXT INDEX ft_search (title, research_goal, summary),
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
  FOREIGN KEY (creator_id) REFERENCES users(id),
  FOREIGN KEY (editor_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='访谈表';
```

### 3.5 参与人表 (interview_participants)

```sql
CREATE TABLE interview_participants (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  interview_id BIGINT NOT NULL,
  name VARCHAR(128) NOT NULL COMMENT '参与人姓名',
  role TINYINT NOT NULL COMMENT '角色：1-访谈者 2-受访者',
  organization VARCHAR(256) COMMENT '所属组织/公司',
  title VARCHAR(128) COMMENT '职位/头衔',
  sort_order INT DEFAULT 0 COMMENT '排序',
  INDEX idx_interview_id (interview_id),
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='访谈参与人表';
```

### 3.6 转写文本表 (transcripts)

```sql
CREATE TABLE transcripts (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  interview_id BIGINT NOT NULL,
  participant_id BIGINT COMMENT '发言人 ID',
  speaker_label VARCHAR(64) COMMENT '说话人标签 (如：受访者 A)',
  content TEXT NOT NULL COMMENT '转写内容',
  start_time_ms INT NOT NULL COMMENT '开始时间 (毫秒)',
  end_time_ms INT COMMENT '结束时间 (毫秒)',
  is_answer BOOLEAN DEFAULT FALSE COMMENT '是否为受访者回答',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_interview_id (interview_id),
  INDEX idx_participant_id (participant_id),
  INDEX idx_start_time (start_time_ms),
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  FOREIGN KEY (participant_id) REFERENCES interview_participants(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='转写文本表';
```

### 3.7 摘要表 (summaries)

```sql
CREATE TABLE summaries (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  interview_id BIGINT NOT NULL,
  transcript_id BIGINT COMMENT '关联的转写片段',
  content JSON NOT NULL COMMENT '摘要内容 (bullet 列表)',
  category VARCHAR(64) COMMENT '分类标签 (观点/事实/行为证据等)',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_interview_id (interview_id),
  INDEX idx_transcript_id (transcript_id),
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  FOREIGN KEY (transcript_id) REFERENCES transcripts(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='摘要表';
```

### 3.8 追问建议表 (follow_up_suggestions)

```sql
CREATE TABLE follow_up_suggestions (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  interview_id BIGINT NOT NULL,
  transcript_id BIGINT COMMENT '触发追问的转写片段',
  question TEXT NOT NULL COMMENT '追问问题',
  reason TEXT COMMENT '推荐理由',
  priority TINYINT DEFAULT 2 COMMENT '优先级：1-高 2-中 3-低',
  category VARCHAR(64) COMMENT '追问类型 (深挖原因/验证行为/澄清矛盾等)',
  status TINYINT DEFAULT 1 COMMENT '状态：1-待处理 2-已采纳 3-已跳过',
  adopted_at DATETIME COMMENT '采纳时间',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_interview_id (interview_id),
  INDEX idx_transcript_id (transcript_id),
  INDEX idx_status (status),
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  FOREIGN KEY (transcript_id) REFERENCES transcripts(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='追问建议表';
```

### 3.9 附件表 (attachments)

```sql
CREATE TABLE attachments (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  interview_id BIGINT NOT NULL,
  file_name VARCHAR(256) NOT NULL COMMENT '文件名',
  file_url VARCHAR(512) NOT NULL COMMENT '文件 URL',
  file_size BIGINT COMMENT '文件大小 (字节)',
  file_type VARCHAR(64) COMMENT '文件类型',
  uploaded_by BIGINT COMMENT '上传人',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_interview_id (interview_id),
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  FOREIGN KEY (uploaded_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='附件表';
```

### 4.4 实时访谈

#### POST /api/interviews/:id/start

**响应：**
```json
{
  "code": 200,
  "data": {
    "sessionId": "session_xxx",
    "sseUrl": "/api/interviews/:id/stream"
  }
}
```

#### POST /api/interviews/:id/audio
上传音频片段（实时录制时分片上传）

**请求：** `multipart/form-data`
- `audio`: Blob 数据
- `chunkIndex`: 分片序号

#### POST /api/interviews/:id/upload
上传音频文件

**请求：** `multipart/form-data`
- `file`: 音频文件

#### GET /api/interviews/:id/stream
SSE 实时推送流

**推送事件类型：**
```
event: transcript
data: {"participantId": 2, "content": "...", "startTimeMs": 1000}

event: summary
data: {"transcriptId": 1, "bullets": ["观点 1", "观点 2"]}

event: suggestion
data: {"question": "为什么...?", "reason": "识别到...", "priority": 1}

event: gap
data: {"type": "missing_behavior", "message": "缺少行为证据"}
```

#### POST /api/interviews/:id/suggestions/:suggestionId/adopt
采纳追问建议

#### POST /api/interviews/:id/suggestions/:suggestionId/skip
跳过追问建议

#### POST /api/interviews/:id/suggestions/refresh
刷新追问建议

## 5. 核心流程

### 5.1 实时访谈流程

```
用户                        前端                       后端                      通义听悟
 |                          |                         |                           |
 |-- 开始访谈 -------------->|                         |                           |
 |                          |-- start() -------------->|                           |
 |                          |                         |-- 创建 session             |
 |                          |<-- sessionId, sseUrl ---|                           |
 |                          |                         |                           |
 |-- 录音 ------------------>|                         |                           |
 |   (MediaRecorder)        |                         |                           |
 |                          |-- audio chunk --------->|                           |
 |                          |   (每 5 秒分片)            |                           |
 |                          |                         |-- 累积音频 ---------------->|
 |                          |                         |<-- 转写结果 ----------------|
 |                          |<-- SSE: transcript -----|                           |
 |                          |   (展示转写)              |                           |
 |                          |                         |-- 调用 LLM 生成摘要 -------->|
 |                          |<-- SSE: summary --------|                           |
 |                          |   (展示摘要)              |                           |
 |                          |                         |-- 调用 LLM 生成追问 -------->|
 |                          |<-- SSE: suggestion ---- |                           |
 |                          |   (展示追问建议)          |                           |
 |                          |                         |                           |
 |-- 结束访谈 -------------->|                         |                           |
 |                          |-- complete() ---------->|                           |
 |                          |                         |-- 生成总结                 |
 |                          |                         |-- 更新状态                 |
 |                          |<-- 完成 ----------------|                           |
```

### 5.2 SSE 推送格式

```javascript
// 后端推送格式
res.write(`event: transcript\ndata: ${JSON.stringify(data)}\n\n`);
res.write(`event: summary\ndata: ${JSON.stringify(data)}\n\n`);

```

## 8. 性能与优化

### 8.1 性能目标

| 指标 | 目标 |
|------|------|
| 首屏加载时间 | < 2s |
| 转写延迟 | < 5s |
| 摘要生成延迟 | < 3s |
| 追问建议延迟 | < 3s |
| 整体延迟 | < 10s |

### 8.2 优化策略

1. **前端懒加载**：路由级别代码分割
2. **音频分片上传**：每 5 秒上传一次，避免大文件阻塞
3. **SSE 增量推送**：避免轮询，实时推送
4. **LLM 异步处理**：摘要和追问使用任务队列异步生成
5. **数据库索引**：关键查询字段建立索引
